# Public archive release validation

The public checkout is maintained separately from operational collection. Only selected C++ sources/headers, synthetic tests, three portable archive tools and neutral documentation/configuration/deployment examples are included. Working configuration, captures, link inventory, live metrics, operational context/checkpoints, pilot wrappers, logs, SQLite state/reference, spool and backups are excluded. Existing BSD-2-Clause license and origin attribution are preserved. No live collector or VM service was changed, restarted or used by these tests.

## Checks for this revision

Release configuration/build succeeded with the available GCC/CMake toolchain, libcurl and SQLite development libraries. All 18 CTest cases passed across the initial run and targeted reruns after fixes: decoder, PCAP, live queues/sockets, receiver/config integration, aggregation, bounded diagnostics, delivery faults, archive configuration/journal/boundary, independent archive delivery, synthetic migration, wait/lock and recovery/cancellation tools. HTTP/UDP tests use temporary loopback endpoints and synthetic input; they do not validate a production deployment or complete long-duration historical migration.

Publication checks exposed two fixture path assumptions and a transient SQLite read-only registry lock. The fixture tests now resolve their script root independently of cwd and replace the configured state path without depending on an operational default. Registry inspection uses a bounded 1s SQLite busy timeout; a controlled exclusive-lock test covers this behavior. Archive journal/integration/migration passed again after the fix. These changes are in the public sources only; running operational binaries were not replaced.

The three-source/four-archive example passed --check-config after substituting only the installed knownlinks path with the distributed neutral example and the state directory with an absent temporary path. Validation does not bind the example addresses or initialize operational state. The fully commented fifth archive remains inactive.

All supplied collector/VM unit examples passed systemd-analyze verify in an isolated temporary root with executable and target placeholders. Units were not installed or started. This is static verification, not a VM deployment test. The compatibility minute unit must not be enabled together with the separately named minute instance. Collector shutdown timeout is 120s for the four-archive example; runtime budget must be reviewed when changing count/timeouts.

README, installation, configuration, architecture, archive administration and query docs describe interval bytes and UTC start timestamps, direct aggregation from shared final minutes, durable state/spool boundaries, explicit bootstrap and known partial/gap coverage. Four VM examples use separate storage/ports with matching 1d/7d/31d/370d retention and dedup=1s. Official single-node documentation was consulted for storage/retention/dedup semantics; the existing release/checksum installation example is retained, not presented as an installed version or resource recommendation. No full raw history export, live capture, production migration, crash/power-loss test or resource forecast was performed for publication.

The selected file inventory, diff whitespace and staged content are checked before commit. Only documentation IP prefixes and loopback endpoints are used. Synthetic policy ASNs use documentation/private values; no operational policy is copied. Generic ignored directory patterns are not operational paths. README links to the separately installed AS-stat-BE-web repository without an operational server address.
